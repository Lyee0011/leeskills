# 横纵分析法

用两条线解释同一个对象：**它如何走到今天，以及它在同类与替代方案之间处于什么位置。** 最后把两条线连接起来，说明历史选择如何形成当前优势、限制和未来可能性。

## 明确研究范围

从用户请求中确定研究对象、研究用途、读者和截至日期；必要时界定地区、产品版本或具体领域。能合理推定的直接说明假设，只有会改变研究方向的歧义才提问。研究对象可以是公司、产品、技术、方法、理念或制度，不把所有对象强行写成商业公司。

篇幅服从用户要求。没有指定篇幅时，按原方法的深度报告定位规划：纵向约 6,000—15,000 字、横向约 3,000—10,000 字、横纵交汇约 1,500—3,000 字，全文约 10,000—30,000 字，具体随对象复杂度与材料量调整。字数是深度参考，不是凑字指标；新生或资料少的对象可以更短。长稿超出单次交付能力时，合理分篇并说明已完成和待完成部分，不把提纲冒充全文。用户要快速判断时，保留两轴与交汇结论，压缩叙述。

## 先搭证据，再写判断

- 建立两份工作底稿：关键历史节点及来源、同类对象与共同对比维度。优先解决会影响结论的事实缺口，再追补背景细节。
- 对“当前”、价格、规模、版本和竞争格局核查最新来源，并标明截至日期。若没有可用检索能力，说明材料范围和时效限制。
- 技术事实优先采用论文、官方文档、原始代码与可复核测试；公司事件优先采用公告、财报、监管文件及当事人材料。争议和复杂动机需要交叉核对，不把官方自述当作完整事实。
- 为关键论断保留具体来源、事件日期与来源发布日期，正文就近引用。区分公开发布、正式上线、首次提出等不同节点，不只沿用一个模糊年份。
- 明确区分事实、当事人解释、分析者推断和预测。无法确认的数值、动机或因果关系保留未知，不补造精确答案。

## 纵向：历史中的选择与后果

追溯对象诞生前的问题：什么需求、技术条件、思想背景或制度环境使它成为可能；有哪些核心推动者；初始形态和定位是什么。

沿时间线选取真正改变轨迹的节点。公司或产品可关注版本、融资、团队、架构、战略、合作、用户里程碑和争议；技术或理念可关注前驱、首次提出、验证、分歧、修正、传播和应用。只使用与对象有关的维度。

对每个重要转折尽量回答：

1. 当时要解决什么问题，面临哪些资源与环境约束？
2. 有哪些可行选项，最终选择了什么？公开材料怎样解释这个选择？
3. 选择带来了什么结果与代价，又怎样影响下一阶段？

把节点写成有因果线索的叙事。没有证据时只能说先后发生或提出可能机制，不能把时间顺序写成已证实的因果。解释当时的选择时使用当时可获得的信息，避免用后来的成功或失败倒推“必然”。人物、细节和时代背景服务于理解转折，不靠编造场景、对话或内心活动增加故事感。

## 横向：同一切面上的真实差异

先说明可比对象为什么可比：它们解决同一需求、服务相近人群，或争夺同类资源。理念与方法可比较替代理论及适用边界；制度可比较不同地区或组织的做法，不必称为竞品。

| 竞争／同类情况 | 处理方式 |
| --- | --- |
| 未发现直接可比对象 | 说明检索范围，研究独特性、壁垒、间接替代和潜在进入者；不要把“没找到”写成“绝不存在” |
| 只有 1—2 个主要可比对象 | 逐一深入比较，解释选择各自方案的现实理由 |
| 可比对象较多 | 选择 3—5 个代表性对象，覆盖主要路线或用户群，交代选择依据，其余概述 |

在共同维度下比较，按研究用途取舍：

- 核心技术路线、方法、假设或底层逻辑。
- 产品形态、商业模式、组织方式、目标用户与使用场景。
- 优势、短板、限制、资源投入、价格或规模。
- 实际用户如何使用，与官方定位有何偏差。
- 在领域中的位置：填补哪类空白，与谁直接竞争，哪些用户更适合它。

保持比较口径一致：时间、地区、版本、价格档位、单位和测量条件尽量对齐；做不到就注明差异。实测、厂商宣称、估算不能混在同一列当作同等证据；未知项不填零，也不据此排出完整名次。

用户口碑要说明来自什么群体、平台和时间段，注意幸存者偏差与不同场景。用多条独立反馈识别反复出现的问题，不把个别帖子、营销案例或社区声量当成总体满意度。表格用于快速对照，正文解释取舍，不逐格复述参数。

## 横纵交汇：从历史解释当前位置

这一部分给出两轴结合后才看得出的判断，不能只是前文缩写。可沿以下问题展开：

- 哪个历史选择造就了今天的优势，又留下了什么路径依赖？
- 当前差异是长期积累、暂时窗口，还是尚未验证的宣传？
- 曾经奏效的策略，在新的竞争条件下是否仍适用？
- 哪些机会或风险有明确的事实基础？什么条件变化会推翻当前判断？

让综合判断呈现可检查的链条：历史选择 → 今天可观察的结果 → 与替代方案的差异 → 有条件的未来判断。预测写出前提与不确定性；不为了显得深刻而添加无依据的行业结论。

## 交付方式

默认顺序是简短研究边界、纵向发展叙事、横向比较、横纵交汇。用户指定了其他结构时按其要求调整，保留方法的核心。

写得像清楚、扎实的深度报道：段落围绕问题和转折展开，用具体细节替代套话；纵向不写成流水年表，横向不写成参数表的文字版。判断必须能追溯到事实，来源与时间靠近相应论断，重要限制不藏在结尾。

交付前核对：对象身份与同名对象是否混淆、事件时间是否准确、历史节点是否遗漏决定性转折、同类选择是否有偏、比较口径是否一致、关键来源是否支持对应论断，以及横纵交汇是否真正产生了新判断。
