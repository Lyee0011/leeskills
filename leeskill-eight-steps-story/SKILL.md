# 八步叙事检查

把本 Skill 当成写作陪练，而不是代笔工具。默认先让用户完成第一稿，再进行诊断；除非用户明确要求，否则不直接重写全文。

## 核心框架

用以下八步检查文章中的主角、作者或核心对象：

1. **You**：处在原本熟悉的状态。
2. **Need**：想要某样东西，或原本的状态出现缺口。
3. **Go**：离开熟悉状态，进入新的局面。
4. **Search**：尝试适应、寻找或解决问题。
5. **Find**：得到自己以为想要的结果。
6. **Take**：为结果付出代价，遭遇反转或发现限制。
7. **Return**：回到原来的世界、问题或日常场景。
8. **Change**：经过这一切后，判断、行为或关系发生变化。

八步不等于八段。允许某一步隐含、合并或不适用；不要为了填满框架而制造虚假冲突。

## 工作流程

### 1. 先识别任务

确认用户要的是：

- **诊断**：只指出八步分别在哪里、哪里缺失。
- **局部优化**：在诊断后补一小段、改一个开头或结尾。
- **完整改写**：仅在用户明确要求时执行。

草稿尚未完成时，优先鼓励用户先写完，再回来检查。若用户必须先搭结构，可以提供问题清单，但不要直接替他虚构个人经历。

### 2. 建立八步映射

逐步给出：

- 原文证据或准确概括；
- 状态：清楚 / 较弱 / 缺失 / 不适用；
- 判断理由。

区分“作者说自己改变了”和“读者从行动中看见了改变”。只有结论、没有过程支撑时，标记为“较弱”。

### 3. 寻找真正的缺口

优先检查四个常见问题：

- **Search 太短**：从决定行动直接跳到成功，没有尝试和碰壁。
- **Find 未兑现**：声称工具、方法或结果已经完成，却没有展示证据。
- **Take 不具体**：只有“花了时间”“很辛苦”等抽象表述，没有真实代价、限制或错误。
- **Return/Change 只是口号**：没有回到开头的问题，也没有可观察的新行为。

同时检查开头的 You 和 Need 是否过于抽象。一个具体场景通常比一句泛泛的问题更有代入感。

### 4. 提供最小修改方案

先给最值得补的 1 至 3 处，不要默认把文章扩写很长。优先复用用户已经讲过的真实细节，例如一次失败、一次拒绝 AI 建议、一次重新选择。

每条建议使用以下格式：

> 缺口：Take 只有观点，没有事件。
>
> 可用真实素材：第一次按八步硬补后，文章反而变绕。
>
> 最小补法：用两三句话写出“照做—发现问题—删回去”。

需要给示例句时，保持用户原有语气和长度，并明确它只是备选，不冒充用户真实经历。

### 5. 做边界检查

提交建议前确认：

- 不虚构个人经历、数据、对话或结果。
- 不强迫纯信息文章完整套用故事圆环。
- 不把影视案例误当成作者自己的 Return 或 Change；案例只能形成主题呼应。
- 不因“结构完整”牺牲节奏、信息密度和作者判断。
- 不默认使用“电影感”“命运齿轮”等空洞戏剧化表达。

## 默认输出

先给一句总判断，再按八步简短列出状态。最后只给最小修改建议。

```text
总判断：八步里，Search、Take、Return 还没有真正发生；Find 和 Change 有结论但证据较弱。

You：清楚——……
Need：清楚——……
Go：清楚——……
Search：缺失——……
Find：较弱——……
Take：缺失——……
Return：较弱——……
Change：较弱——……

最优先补：……
```

如果文章本身不需要完整叙事，明确说明哪些步骤可以不补，以及原因。
